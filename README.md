# 放下 · Let Go

人很小，背包很大，山壁很陡。

背包里有奖杯、一封没寄出的信、戒指和一张旧照片。每一件都有重量。你可以放下，也可以全部带到山顶；到了门前，还可以回头去捡。

**开始攀登：[jeromeyu0007.github.io/Drop](https://jeromeyu0007.github.io/Drop/)**

## 操作

鼠标、触摸或空格，只有按住与松开。

- **按住蓄力，松开发力。** 看摆动和预测弧线，选择松手的时刻。弧线接近可抓住的目标时会变暖。
- **失手时仍可以伸手。** 下坠时按住会增加抓取范围；路过够得着的岩点会接住。完全错过才落回山脚。允许越过下一岩点。最陡的强风段，满负重时需要在下落阶段再次按住，主动伸手接握。
- **抓稳之后决定留什么。** 四处休息点保持悬挂，身体停稳后打开背包。每处可以放下一件仍携带的物品，也可以选择「继续」。重包起动更慢、接住后回稳更久，变轻后这些惯性会减小。
- **山顶按住再松手进门。** 有遗失物时，在结局中选择「下山去捡」，才会切换到独立的下降曲线。下山时按住稳住身体，让弧线接近下方岩点，再松手下放；接住后，下一次下放必须重新按住、松开。停留或持续按住都不会被计时强制脱手。
- **接近遗失物会捡回。** 捡回最后一件后，操作恢复为向上攀登，返程天气仍会保留。结局只取决于最后带着什么，不区分是否曾经丢过。
- 结局后可「重玩」；有遗失物时另有「下山去捡」。16 种结局会留下印记。

当前路线有 47 个岩点，从 8 米起点到约 193 米山顶。四处丢物节点把路线分成五段，后段需要更准确地掌握松手时机，风和天气也逐段加重。放下物品会减轻身体负担，天气继续随高度变化。

右上角「重来」开启新的一轮。电脑可按 Esc 暂停或继续。离开页面时游戏暂停，并尝试在本机保存当下状态；回来后点「继续攀登」。这是中断恢复，不是失败后回退的检查点：坠落、遗失物和本轮选择都会保留。浏览器清理本地数据或路线更新后，本局恢复可能失效。

## 画面与运行

人物、岩壁、远山、天气、物品和声音全部由代码生成，没有下载的图片、模型或音频资源。岩石裂纹、织物和环境反射在启动时生成；人物衣服沿真实关节连续变形，双手抓点与全身发力使用同一套骨架。远山、积雪、雾层和冷暖照明随高度变化。Three.js 随游戏本地提供，不依赖外部 CDN。

支持横竖屏；慢设备会自动降低阴影、材质细节、粒子和渲染分辨率。WebGL 上下文丢失时暂停，恢复后由玩家继续。暂停时只保留静止画面；静音覆盖风声和所有音效。

运行时文件为 `index.html`、`surface.js`、`game.js`、`world.js`、`character.js`、`render.js` 和 `vendor/three.min.js`，总大小不足 1 MB。**10 MB 限制按未压缩的完整运行资源计算**，由测试和构建强制检查；浏览器内存与显存另计。场景生成不需要联网。

本地预览（Python 3）：

```sh
python3 -m http.server 8123
```

打开 `http://localhost:8123/`。物理模块 `game.js` 不依赖 DOM，前端以固定 120 Hz 步进运行。

## 验证

Node.js 22 或更新版本：

```sh
npm test
npm run test:human
```

`npm test` 包括：

- 完整运行资源小于 10,000,000 字节；所有引用为本地文件且实际存在。
- 岩点与高低精度岩壁的贴合检查；真实三角表面、全身碰撞体积和袖口／鞋底检查。
- 人物骨长、关节方向、抓握锚点、全身摆动和胸口过手；释放、接住、悬挂休息与山顶站立的连续性。
- 五段天气／风力、空满背包发力和恢复时间，以及多个风相位下的上下山松手窗口。
- 16 种固定背包及 16 种自然取舍过程的登顶；四件物品分别或全部丢弃、登顶、下山拾回、再登顶。
- 上下山都无计时强制脱手；选择下山立即切换曲线，每次下放要求独立操作；沿途岩点抓取和严重失误真实坠底。
- 失误恢复采样，分别报告原点接住、下方接住和落地，不把回抓原点冒充下方接住。

`test:human` 是**知道最佳窗口的自动玩家加操作误差**：标准差 80ms，另有 10% 概率产生 200–400ms 的较大误差。它用于检查系统是否会卡死和误差如何累积，不模拟学习、观察、情绪和设备延迟，也不能证明真人首玩所需时间。

浏览器测试需要 Playwright 和 Chromium：

```sh
npm ci
# 预览服务器运行后：
node test/browser-ui.js
node test/browser.js --fast
node test/browser.js --fast --fall
node test/browser.js --mobile --screens
# 侧面检查空包 / 满包的蓄力、双力臂、释放与接住：
npm run test:motion
# 下载请求、三档画质、帧耗时、内存及反复切换画质的资源检查：
npm run test:visual
```

默认使用 `/usr/bin/chromium`，其他路径可设置 `CHROMIUM_PATH`。`browser.js` 的完整旅程通过鼠标事件操作，不直接设置人物位置；`--fast` 仅降低画质与视口大小，物理规则不变。`browser-ui.js` 则用隔离场景验证触摸、静音、中断恢复和短横屏布局。常规截图默认写入 `/tmp/drop-validation`，动作序列默认写入 `/tmp/drop-motion`（含可打开的 `index.html` 连续帧图版），可用 `DROP_CAPTURE_DIR` 指定目录。

`test:visual` 在报告中区分下载体积、垃圾回收后的 JavaScript 堆、数组存储和渲染目标估算值，记录实际 GPU 信息。软件渲染器的测量不能代表手机或独立显卡帧率；显存估算也不包含浏览器和驱动的全部开销。

## 部署

`npm run build` 检查资源预算和脚本缓存版本，将全部运行文件复制到 `_site` 目录，可交给任意静态服务器。可以重复构建；目标目录若含未知文件或符号链接，会停止并保留原文件。GitHub Actions 会先执行核心测试，通过后才将 `main` 部署至 GitHub Pages。只发布运行时文件，不上传测试工具或开发依赖。修改脚本后同步更新 `index.html` 中的资源版本，避免旧缓存混用。
