# 放下 · Let Go

人很小，背包很大，山壁很陡。

背包里有奖杯、一封没寄出的信、戒指和一张旧照片。每一件都有重量。你可以放下，也可以全部带到山顶；到了门前，还可以回头去捡。

**开始攀登：[jeromeyu0007.github.io/Drop](https://jeromeyu0007.github.io/Drop/)**

## 操作

鼠标、触摸或空格控制蓄力和释放；一次按住、松手即可完成正常攀爬，抓稳后可以切换方向。

- **按住蓄力，松开发力。** 看摆动和预测弧线，选择松手的时刻。弧线接近可抓住的目标时会变暖。
- **手够到目标岩点便会抓住，无需再次按压。** 正常跃起和主动下放都会伸手接下一处岩点。身体沿实际轨迹移动，碰不到岩点不会被拉过去。失手下坠后可按住短暂伸手自救；伸手过期后，需要松开再按才会重试。完全错过会落回山脚。
- **上攀和下放随时可以换。** 抓稳岩点后点「↑ 上攀 / ↓ 下放」，或按 W / S、↑ / ↓；空中不能换向，山脚不能再下放，山顶不能再上攀。切换会取消当前蓄力，重新按住、松开才会出发。下放采用独立曲线：按住稳住身体，松手向下，手够到下一岩点便会抓住。接住后继续按着不会自动发起下一次下放。
- **抓稳之后决定留什么。** 四处休息点保持悬挂，抓住后打开背包。每处可以放下一件仍携带的物品，也可以选择「继续」。重包起动更慢、接住后回稳更久，变轻后这些惯性会减小。
- **山顶按住再松手进门。** 有遗失物时，在结局中选择「下山去捡」开始返程；进门前也可以直接选择「↓ 下放」。不需要长按来触发下山。停留或持续按住都不会被计时强制脱手。
- **接近遗失物会捡回。** 拾齐后仍保留你选择的方向，可以自行切换上攀；返程天气继续保留。结局只取决于最后带着什么，不区分是否曾经丢过。
- 结局后可「重玩」；有遗失物时另有「下山去捡」。16 种结局会留下印记。

当前路线有 47 个岩点，从 8 米起点到约 193 米山顶。四处丢物节点把路线分成五段，后段需要更准确地掌握松手时机，风和天气也逐段加重。重包蓄力更慢、有效发力时机更窄，接住后回稳更久，侧风影响也更大。放下物品会减轻身体负担，天气继续随高度变化；途中改为下放不会凭空加重天气，山顶返程的风暴状态则会保留。

右上角「重来」开启新的一轮。电脑可按 Esc 暂停或继续。离开页面时游戏暂停，并尝试在本机保存当下状态；回来后点「继续攀登」。这是中断恢复，不是失败后回退的检查点：坠落、遗失物、本轮选择和上下方向都会保留，旧按压会取消。兼容上一版存档；浏览器清理本地数据或路线更新后，本局恢复可能失效。

## 画面与运行

人物与山体几何、动画、天气和声音由代码生成，表面细节使用 12 张本地 WebP 贴图：岩石、织物和皮革各有颜色、法线与粗糙度贴图，另外两张用于云层天空和环境反射，一张用于远处雪山。前 11 张素材来自 Poly Haven 的 CC0 摄影／扫描资源；雪山远景是项目专用生成画面。来源、作者、尺寸、处理方式和校验值见 [资源清单](assets/manifest.json) 与 [素材署名](assets/CREDITS.txt)。图片合计约 4.07 MB；没有外部模型或音频下载。

人物衣服沿关节连续变形，双手抓点、全身发力与身体碰撞使用同一套姿态。服装与皮革有缝线、褶皱和材质差异；岩面湿润反光、人物积霜、远山积雪、雾和降水随天气变化。天空与环境反射来自同一片云层；环境源是经过色调映射的普通图片，不是 HDR 文件。Three.js 和贴图随游戏本地提供，不依赖外部 CDN。

支持横竖屏；慢设备会自动降低阴影、材质细节、粒子和渲染分辨率。WebGL 上下文丢失时暂停，恢复后由玩家继续。暂停时只保留静止画面；静音覆盖风声和所有音效。

运行资源包含 `index.html`、`surface.js`、`game.js`、`world.js`、`character.js`、`render.js`、`vendor/three.min.js` 和代码引用的 12 张本地贴图，总计约 4.96 MB。**完整运行资源必须低于 5,000,000 字节，按 HTTP 压缩前的文件大小合计**，测试和构建都会检查；浏览器运行内存与显存另计。运行 `node test/budget.js` 可取得当前版本的精确总量和逐文件明细，资源全部加载后不需要外部联网请求。

本地预览（Python 3）：

```sh
python3 -m http.server 8123
```

打开 `http://localhost:8123/`。物理模块 `game.js` 不依赖 DOM，前端以固定 120 Hz 步进运行。

## 验证

Node.js 22 或更新版本：

```sh
npm test
npm run test:human
```

`npm test` 包括：

- 完整运行资源小于 5,000,000 字节；所有引用为本地文件且实际存在，贴图计入预算。
- 岩点与高低精度岩壁的贴合检查；真实三角表面、全身碰撞体积和袖口／鞋底检查。
- 人物骨长、关节方向、抓握锚点、全身摆动和胸口过手；释放、接住、悬挂休息与山顶站立的连续性。
- 五段天气／风力、空满背包发力和恢复时间，以及上下山松手窗口与主动伸手窗口；难度测试另取代表岩点的多个风相位。
- 16 种固定背包及 16 种自然取舍过程的登顶；四件物品分别或全部丢弃、登顶、下山拾回、再登顶。
- 上下山都无计时强制脱手；抓稳后可以往返切换方向，空中换向无效；切换取消旧蓄力，拾齐物品不会强制改为上攀。
- 正常上攀与主动下放只需一次按住、松手，实际够到目标才会接住；失手下坠没有自动吸附。自救按压有有限时窗，超距或过期不能抓住。

`test:human` 是**知道有效窗口的自动玩家加操作误差**：松手误差标准差为 80ms，另有 10% 概率在松手时增加 200–400ms 的较大误差。正常攀爬只执行一次按住、松手，不会在失误后自动补上自救按压。它用于观察失误如何累积，不模拟学习、观察、情绪和设备延迟，也不能证明真人首玩所需时间。

浏览器测试需要 Playwright 和 Chromium：

```sh
npm ci
# 预览服务器运行后：
node test/browser-ui.js
node test/browser.js --fast
node test/browser.js --fast --fall
node test/browser.js --mobile --screens
# 侧面检查空包 / 满包的蓄力、双力臂、释放与接住：
npm run test:motion
# 下载请求、三档画质、帧耗时、内存及反复切换画质的资源检查：
npm run test:visual
```

默认使用 `/usr/bin/chromium`，其他路径可设置 `CHROMIUM_PATH`。`browser.js` 的完整旅程先在状态副本上规划松手与伸手时机，再通过真实鼠标事件操作，方向选择使用页面按钮，不直接设置人物位置；`--fast` 仅降低画质与视口大小，物理规则不变。`browser-ui.js` 则用隔离场景验证触摸、方向按钮与快捷键、旧手势取消、静音、旧存档迁移、中断恢复和短横屏布局。常规截图默认写入 `/tmp/drop-validation`，动作序列默认写入 `/tmp/drop-motion`（含可打开的 `index.html` 连续帧图版），可用 `DROP_CAPTURE_DIR` 指定目录。

`test:visual` 在报告中区分下载体积、垃圾回收后的 JavaScript 堆、数组存储和渲染目标估算值，记录实际 GPU 信息。软件渲染器的测量不能代表手机或独立显卡帧率；显存估算也不包含浏览器和驱动的全部开销。

## 部署

`npm run build` 检查资源预算和脚本缓存版本，将全部运行文件复制到 `_site` 目录，可交给任意静态服务器。可以重复构建；目标目录若含未知文件或符号链接，会停止并保留原文件。GitHub Actions 会先执行核心测试，通过后才将 `main` 部署至 GitHub Pages。只发布运行时文件，不上传测试工具或开发依赖。修改脚本后同步更新 `index.html` 中的资源版本，避免旧缓存混用。
